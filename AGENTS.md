## Workflow Enforcement

Planning agents **must** follow these rules when working on this project:

### Before Planning Any Phase

1. Read `.planning/PROJECT.md` for project context, constraints, and key decisions
2. Read `.planning/REQUIREMENTS.md` for the phase's requirement IDs
3. Read `.planning/ROADMAP.md` for the phase goal and success criteria
4. Read `.planning/STATE.md` for current position and blockers
5. Read `.planning/codebase/` for existing conventions to match

### During Execution

- **Feature branch only**: All commits go to `feature/task-comments`. Never commit directly to `main`.
- **Small focused commits**: Each commit = one logical step. No "wip" or "fix" commits.
- **AI disclosure**: Add `Co-Authored-By` trailer to commits where AI meaningfully co-authored the code.
- **Server-enforced permissions**: Never rely on UI-only authorization checks.
- **Follow existing patterns**: Match router, model, schema, hook, API module, and i18n conventions.

### Success Gate

A phase is complete when **all success criteria in ROADMAP.md** are met — not just when code compiles.

Phase 2 (Backend) success criteria include:
- `GET /api/tasks/{task_id}/comments` returns comments with author, timestamp, body, edited flag
- Non-author/non-admin `DELETE` returns 403
- Non-workspace-members cannot create comments (403)

### Must-Haves (from `candidate-task.md`)

These are non-negotiable for the PR to be considered complete:

- [ ] View comments on a task
- [ ] Post a new comment
- [ ] Edit own comment
- [ ] Delete own comment
- [ ] Workspace admin/owner delete any comment
- [ ] Edited comments visually distinguishable
- [ ] Permissions enforced server-side
- [ ] All supported UI languages (English + Japanese)
- [ ] Empty, loading, and error states handled

### Out of Scope (do not build unless all must-haves are complete)

- Pagination / load more
- `@mention` autocomplete
- Markdown / rich text
- Optimistic UI
- Activity timeline integration
- Real-time updates
- Notifications

## Research Findings

See `.planning/research/SUMMARY.md` for the full synthesis. Key points:

- **Stack**: No new runtime dependencies needed — use existing FastAPI, SQLAlchemy, React Query, and i18n infrastructure
- **Table stakes**: CRUD, permissions, author/timestamp display, edited indicator, async states, i18n
- **Critical pitfalls**: UI-only permission checks, weak migration, scope creep, frontend state drift
- **Recommended migration**: `015_task_comments.py` after current head `014_memory_audit_events`
